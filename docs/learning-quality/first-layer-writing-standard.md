# 知识点第一层写作与审核标准

第一层是一篇准确、自洽、可以独立读懂的概念介绍。读者完成阅读后，应能说明概念是什么、基本怎样工作、与相关概念有什么区别，并能判断具体情形是否符合定义。本文适用于知识字典中的全部知识点，也适用于同步到计算机与人工智能、量化两个源仓库的分层资料。

## 读者定位

读者具备数学博士的推理能力，但可能没有当前领域的基础知识。保留准确性和必要深度，解释陌生的领域术语。不能默认读者已经知道寄存器、指令或吞吐量，也不能因为其数学背景而默认其偏好形式化符号。

## 必要基础与定义

在定义之前或首次使用时，解释理解目标概念必需的关键对象。例如，介绍 CPU 时先说明程序、指令和处理器的关系。只补当前解释必需的基础；如果一个词又引出大量新词，应重新选择解释路径，不能靠补一个庞大的术语表来维持原有堆叠。

定义须交代对象本身、基本特征及讨论范围，并能够与容易混淆的对象区分。特点、优势、用途和类比不能代替定义。“CPU 擅长复杂控制，GPU 擅长并行计算”只能作特点概括，不能单独充当定义。

## 工作过程与概念关系

通过连贯的过程，说明对象怎样工作、各部分有什么关系，以及主要差异从何而来。第一层不能止于定义和用途的罗列。基本机制可以讲清，但不必为介绍 CPU/GPU 先引入抽象机状态转换或完整硬件实现。

每引入一个术语，都应能回答它在当前解释中解决什么问题。术语应在需要它的地方解释；指向其他页面的链接不能替代本页必需的说明。明确本页的解释范围，把不影响当前理解的内部细节留给第二层或相关知识点。

## 符号与公式

只有当符号或公式比文字和具体过程更准确、更简洁时才使用，并说明含义、条件和必要单位。数学概念的定义可以需要公式；硬件概念也可以完全不需要公式。不能以符号数量、抽象层级或术语密度衡量专业深度。

加入一段表达前，应判断读者具体多理解了什么。把“执行指令会改变状态”改写成函数表达式，如果不能帮助解释当前概念，就不应占据入门介绍。

## 例子

每个例子明确背景、输入、规则、处理过程及结果，并说明它体现了定义中的哪一点。数据、单位、概率条件、时间范围和比较基线应齐全。简化假设写在相应结论旁边；示意数据、模型结果和实际测量不能混淆。

例子承担解释机制、区别或边界的任务，而不是只在正文后附几个数字。类比和故事可以辅助，但须交代对应关系及边界，不能代替实际对象的说明。不得用同一段通用例子批量套用不同知识点。

## 边界与错误推论

除典型情形外，还应澄清由定义和例子容易产生的错误推论。例如，CPU 也能并行、GPU 也能处理条件判断；计算部分更快不保证整个任务更快；共享读取已有数据不同于等待另一个计算产生结果。

辨析应从本节内容自然展开，不突然要求读者掌握另一套知识体系。限制结论的强度，不能把常见实现当作定义，把特定应用的要求当作整个领域的前置条件。

## 理解练习

根据本节的主要理解目标安排互补的练习，覆盖定义理解、概念区别、过程判断、边界识别及情境应用。题量取决于知识点范围，不规定每节必须凑够六题。不能只围绕同一个局部问题换几种问法。

每题给出充分背景与条件，并有完整的答案和解释。解释判断依据、容易误判的原因，以及哪些条件改变后结论可能不同。练习不得依赖正文尚未介绍的专业知识，不得以“请自行推导”“见第二层”代替答案。涉及计算时，核对中间值、结果、单位和口径。

## 与第二层的分工

第一层建立清楚、准确的概念框架；第二层展开系统推导、证明、逐步计算、应用方法和推广。第一层允许必要的公式、简单计算和基本原理说明，不能机械地把所有“为什么”或所有数学表达都移到第二层。

重写第一层时保留第二层及原始章节中的完整材料。对第二层发现的事实错误，应单独记录并修正，不能通过删除原文或缩短解释掩盖问题。

## 逐篇审核与发布

每个知识点分别检查下列问题，并记录实际发现和修改：

1. 定义是否准确，是否被一句特点或用途概括替代？
2. 解释是否依赖尚未说明的关键术语？必要基础是否足够且适量？
3. 每段内容是否具体帮助理解当前概念？符号是否有实际作用？
4. 例子能否按给定条件复现，结论与假设是否一致？
5. 练习是否覆盖主要理解目标，能否依据正文完成，各题是否有充分解释？
6. 边界、相邻概念及常见误解是否清楚？
7. 英文版本是否完整保留中文版本的条件、论证和例子？
8. 网站与源仓库导出是否保留同一份内容，页面阅读顺序是否正确？

字段齐全、篇幅足够、公式可以显示、练习数量达标，都不能替代内容审核。自动检查只提供结构、翻译覆盖、公式解析、部分算例以及发布完整性的证据。只有全部知识点完成逐篇修改与审核后，才可把本轮工作标记完成，并同步源仓库、构建和部署网站。
