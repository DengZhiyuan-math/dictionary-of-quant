# 幂等处理

概念编号：`concept:quant-idempotent-processing` · [网站双语阅读](https://zhiyuan-deng.pages.dev/dictionary/topic/concept/quant-idempotent-processing/)

## 第一层：概念入门 · 知其然

### 它是什么

幂等处理让同一件事重复送达时，只产生一次该有的账务变化。

### 先看一个例子

同一张收据扫描两遍，不该从钱包扣两遍钱。

### 理解练习

价格和数量相同就一定是重复成交吗？

<details><summary>答案与解释</summary>

不是，不同执行身份可能代表两笔合法交易。

</details>

## 第二层：深入理解 · 知其所以然

围绕推导、计算、应用与推广阅读；下面保留原有推演顺序。

### 从条件一步步推导

1. 把已处理执行身份与现金持仓放入一致状态；见过的同内容执行不再更新。
2. 于是应用一次和重复应用后的账本相同；身份冲突内容必须报警，而非静默忽略。

### 具体输入与计算步骤

同一张收据扫描两遍，不该从钱包扣两遍钱。

1. 现金1000、持仓0，E1买3股×100，费用1，扣301。
2. 第一次后现金699、持仓3；重复E1不再扣款。

计算结果：两次传输仍为699元与3股，不是398元与6股。

### 换到实际问题中应用

恢复断线后重发的成交回报。

1. 持久保存去重身份及应用进度，重启时与账本一起恢复，再处理重放。

应用结论：去重不只活在易丢失的内存集合中。

### 举一反三：改变条件后的完整解答

若E2也是3股、100元、费1，要忽略吗？

<details><summary>变式的推演与答案</summary>

1. E2是新身份且符合协议，应再扣301并加3股。

现金398、持仓6；相同经济内容不等于相同事实。

</details>

### 原有解释与进一步例题


### 金融应用：同一成交事实只能入账一次

交易网关可能重发执行回报，系统重启也可能回放已处理事件。应根据交易协议定义稳定的成交身份，使同一成交不重复改变现金、持仓和费用。成交 ID 的唯一范围可能还需要场所、账户或会话；相同价格和数量并不能证明是同一笔成交。


### 状态公式与持久化边界

设 S 为含去重记录的账本状态，e 为一个执行事件，apply 为入账操作，重复安全要求 \(\operatorname{apply}(\operatorname{apply}(S,e),e)=\operatorname{apply}(S,e)\)。现金、持仓、已处理身份与日志进度必须采用协调的持久化语义，不能只把去重集合放在内存。相同身份却带有冲突内容时应报错并核对，不能当成普通重复静默忽略。


### 例子：E1 重放后持仓仍为三股

初始现金 1,000 元、持仓 0，执行 E1 买入 3 股、每股 100 元、费用 1 元，入账后现金 699 元、持仓 3。E1 再次到达或重启后重放，不应再扣 301 元或把持仓变成 6。若另一笔合法执行 E2 恰好也是 3 股、100 元，它仍是新成交。订单超时的未知结果还需按场所协议查询，不能改 ID 后盲目重发。


### 适用边界与常见误解

同 ID 不同内容属于冲突，不能静默丢弃。
