# 幂等处理

概念编号：`concept:quant-idempotent-processing` · [网站双语阅读](https://zhiyuan-deng.pages.dev/dictionary/topic/concept/quant-idempotent-processing/)

## 第一层：概念入门 · 知其然

### 它是什么

交易网关可能重发执行回报，系统重启也可能回放已处理事件。应根据交易协议定义稳定的成交身份，使同一成交不重复改变现金、持仓和费用。成交 ID 的唯一范围可能还需要场所、账户或会话；相同价格和数量并不能证明是同一笔成交。

### 先看一个例子

若另一笔合法执行 E2 恰好也是 3 股、100 元，它仍是新成交。订单超时的未知结果还需按场所协议查询，不能改 ID 后盲目重发。

## 第二层：深入理解 · 知其所以然

### 状态公式与持久化边界

设 S 为含去重记录的账本状态，e 为一个执行事件，apply 为入账操作，重复安全要求 \(\operatorname{apply}(\operatorname{apply}(S,e),e)=\operatorname{apply}(S,e)\)。现金、持仓、已处理身份与日志进度必须采用协调的持久化语义，不能只把去重集合放在内存。相同身份却带有冲突内容时应报错并核对，不能当成普通重复静默忽略。


### 例子：E1 重放后持仓仍为三股

初始现金 1,000 元、持仓 0，执行 E1 买入 3 股、每股 100 元、费用 1 元，入账后现金 699 元、持仓 3。E1 再次到达或重启后重放，不应再扣 301 元或把持仓变成 6。若另一笔合法执行 E2 恰好也是 3 股、100 元，它仍是新成交。订单超时的未知结果还需按场所协议查询，不能改 ID 后盲目重发。


### 适用边界与常见误解

同 ID 不同内容属于冲突，不能静默丢弃。
