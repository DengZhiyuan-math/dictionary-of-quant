# 延迟

概念编号：`concept:quant-latency` · [网站双语阅读](https://zhiyuan-deng.pages.dev/dictionary/topic/concept/quant-latency/)

## 第一层：概念入门 · 知其然

### 它是什么

延迟是信息产生、接收、处理、发送订单与交易所确认之间耗费的时间。不同环节的延迟分别影响“知道了什么”和“能否及时执行”。

### 先看一个例子

估值在 10:00:00.000 发生变化，你在 5 毫秒后收到并发出撤单，交易所 3 毫秒后处理。即使计算瞬间完成，旧报价仍可能在约 8 毫秒的窗口内被打中。

## 第二层：深入理解 · 知其所以然

围绕推导、计算、应用与推广阅读；下面保留原有推演顺序。

### 参数与公式

若数据在 t₀ 产生、t₁ 到达，数据延迟为 t₁-t₀；订单在 t₂ 发出、t₃ 确认，确认延迟为 t₃-t₂。所有时间戳需统一时钟；收到撤单成功确认前，旧订单可能仍会成交。


### 适用边界与常见误解

报价已发送不代表撤销已在市场生效。

### 领域应用

- [Cancel Latency · 撤单到达、处理与确认的边界](quant-cancel-latency.md)：延迟的共同定义保留在基础页，高频撤单页只明确各段时间与订单仍可成交的窗口。
- [Report Latency · 场所成交与本地获知的时间差](quant-report-latency.md)：复用延迟的端点定义，执行回报应用专门区分场所事实和本地已知状态。
