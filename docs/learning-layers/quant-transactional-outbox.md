# 事务发件箱

概念编号：`concept:quant-transactional-outbox` · [网站双语阅读](https://zhiyuan-deng.pages.dev/dictionary/topic/concept/quant-transactional-outbox/)

## 第一层：概念入门 · 知其然

### 它是什么

交易系统可在同一个本地数据库事务中记录“接受订单并预留风险”和“待发送的订单意图”。事务发件箱里的意图随后由发送器读取和重试，避免本地风险账已变更却找不到发送记录，或已准备发送却没有相应风险预留的双写裂缝。这里记录的是意图，不是交易所已经成交的事实。

### 先看一个例子

持仓 0、限额 10，系统接受买入 8 股的 O1，在同一事务写入预留 8 和待发送 O1。场所接受后，发送器在标记完成前崩溃；恢复时 O1 仍可能待发。不能把它改成新 ID 再买 8 股，应按场所协议复用安全身份或先查询未知结果。Outbox 保住了本地意图，不自动保证外部只成交一次。

## 第二层：深入理解 · 知其所以然

### 原子边界与重试身份

设 H 为已确认持仓，P 为尚未结束订单的预留买入量，L 为简化持仓限额；接受新买单 q 前需在一致边界内检查 \(H+P+q\le L\)，并将 P 增加 q 与带稳定订单 ID 的 outbox 记录一起提交。只有真实回报才能继续推进订单与账本状态。本地事务不包含外部场所，因此发送器仍可能重复发送，需配合协议身份、幂等和对账。


### 适用边界与常见误解

不把外部交易对手自动纳入本地事务。
