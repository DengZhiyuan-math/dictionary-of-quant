# 快照恢复

概念编号：`concept:quant-snapshot-recovery` · [网站双语阅读](https://zhiyuan-deng.pages.dev/dictionary/topic/concept/quant-snapshot-recovery/)

## 第一层：概念入门 · 知其然

### 它是什么

快照给出某序号时的完整状态，增量描述随后变化。按来源和会话跟踪序号；发现缺口时不能继续把不完整订单簿当完整实时簿。应按具体协议恢复快照并衔接之后增量，不能用新的到达时间掩盖缺失事件。

### 先看一个例子

已应用序号10，接着收到12，缺少11，则状态标记不可安全用于新增风险决策。即使随后又收到13也不会自动补齐11。收到覆盖到20的有效快照后，再按协议恢复21及以后的连续更新。快照重置的是行情基准，不是订单与持仓账。

最后序号10期待11，却收到12，说明缺了一个更新；即便13继续到达，也无法知道11曾改变哪个价位。直接把本地序号改为13并称已同步，会把“消息继续流动”误当作“订单簿正确”。快照恢复只修复行情基准，不重置真实资金、成交去重记录或未结订单。
