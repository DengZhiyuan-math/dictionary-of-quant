# 撤单待确认

概念编号：`concept:quant-cancel-pending` · [网站双语阅读](https://zhiyuan-deng.pages.dev/dictionary/topic/concept/quant-cancel-pending/)

## 第一层：概念入门 · 知其然

### 它是什么

发出撤单请求后订单可能仍成交，直到收到相应确认或状态核对。替换委托也涉及原订单引用、版本和在途变化。应分别记录待确认、可执行、部分成交、撤单待确认和终态，不用一个布尔变量假装所有竞态都不存在。

可以手写状态转移表：NEW请求→待确认；接受确认→工作中；部分成交→更新filled与现金；撤单请求→cancel_pending但保持未成交预留；撤单确认→停止该单工作量；迟到真实执行→更新累计成交与账本并对账。取消的是剩余工作量，不会把已经成交的历史变成零。

### 先看一个例子

买8股，先成交3股，再收到相同执行ID，不应变成6股。发撤单并收到取消确认后，又到达取消前发生但传输迟到的2股成交，真实总成交应更新到5。它改变资金和仓位，即使会触发限额警报也不能拒记事实；还需与交易方累计量和时间顺序核对。
