# 事件回放

概念编号：`concept:quant-event-replay` · [网站双语阅读](https://zhiyuan-deng.pages.dev/dictionary/topic/concept/quant-event-replay/)

## 第一层：概念入门 · 知其然

### 它是什么

本地脚本实现一个单标的、整数分价格和整数股数的教学账本，包含行情有效性、委托预留、成交去重、撤单和紧急停止。所有事件来自内置列表，接口不会连接交易所。它只展示声明的状态语义，不实现完整FIX、撮合队列或真实清算。

### 先看一个例子

若扩成真实系统，还需持久事务、连接协议、权限、对账、交易场所规则与独立验证，不能把这个内存案例直接当作生产执行器。

重放两次比较事件结果、每步现金仓位和最终状态的SHA摘要。摘要保证的是这份输入在该逻辑下的一致结果，不证明输入本身没有遗漏。另开独立引擎测试“先接受2股，再缺口与Kill，再收到1股成交”，明确准入阻断与事实记账是不同路径；不能只在正常路径里顺手设置一个Kill标志就称已验证故障。

在项目根目录运行：python examples/research_cases.py --output data/research-results.json。完整步骤及结果解读见docs/RESEARCH_CASES.md；逐行证据保存在examples/output。

### 取消与迟到成交

请求取消并取得模拟确认后，又收到取消前产生的2股迟到执行，真实总成交变5。以每股1000分、每次新执行费用2分、初始现金100000分计，最终现金应为94996分。重复同一执行不再收一次费，取消不清空已有仓位。

撤单请求后upper仍为8，所以再买8继续拒绝；确认后预留释放、upper暂为3；E2迟到买2再扣2002分，得到94996和仓位5。即便该回报会让另一个系统的风险超限，也须先核对并入账。案例的已知订单正成交子集不处理冲正；对真实更正需要专门事件和反向账务。
